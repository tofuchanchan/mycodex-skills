# 输入识别与大纲路由

## 输入类型

### PDF、文档、截图

1. 先确认所有页面或图片都能读取。
2. 提取标题结构、关键主张、数据、图表、注释和来源。
3. 视觉材料需要逐页查看，不能只依赖文本抽取。
4. 把原文事实与解释性推断分开记录。

### 代码仓库或功能实现

1. 明确功能入口、相关模块和用户触发方式。
2. 搜索路由、接口、服务、模型、状态、配置、测试和错误处理。
3. 用可点击的文件与行号作为工程层证据。
4. 只读相关调用链，不要为了“完整”遍历无关代码。
5. 未在代码中找到的业务意图标为 `unknown` 或 `inferred`。

### 专业术语或知识主题

1. 判断术语是否稳定、是否存在版本或行业分歧。
2. 优先一手标准、官方文档、论文或权威机构资料。
3. 区分定义、直觉类比、适用场景、边界、误区和实例。
4. 会随时间变化的事实必须重新核验。

### 用户大纲

先判断完整度和约束强度：

- 章节齐全且用户强调结构：`preserve`。
- 章节不全但方向清楚：`augment`。
- 只有零散要点：通常 `augment`，必要时 `generate` 并把要点映射进去。
- 只有用户明确要求重构：`replace`。

保留不等于照抄。可以改善标题、段落和视觉位置，但不能改变章节意图和顺序。

## 是否直接生成

默认 `generation_mode: direct`。仅在用户明确要求时使用 `plan-only`。以下问题属于阻断项：

- 输入损坏或无权限读取。
- 用户约束彼此冲突。
- 缺失的信息会改变核心结论或整个页面结构。
- 被路由为必需的子 Skill 不存在。

一般性的细节缺失不是阻断项，标为 `unknown` 后继续。
