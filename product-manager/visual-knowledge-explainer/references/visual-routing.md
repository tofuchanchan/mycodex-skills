# 视觉任务路由

## 决策表

| 要解释的内容 | 路由 | 原因 |
|---|---|---|
| 流程、分支、状态机、调用链 | Excalidraw | 节点和方向必须精确 |
| 系统架构、依赖、数据流、角色协作 | Excalidraw | 关系需要可核查 |
| 为什么重要、抽象原则、认知转折 | 小黑插图 | 需要形成心智模型 |
| 误区、张力、取舍、业务隐喻 | 小黑插图 | 精确流程图反而生硬 |
| 规则矩阵、对比、清单、证据 | HTML 表格/卡片 | 便于检索和复制 |
| 章节导航、渐进披露、响应式布局 | visual-explainer | 属于页面编排 |

## 冲突处理

- 同一信息同时像流程又像概念时，先问它是否要求精确复现。要求精确则用 Excalidraw，抽象含义另选不同角度给小黑。
- 不允许 Mermaid 和 Excalidraw重复表达同一核心图。
- 不允许小黑插图承载必须逐字准确的接口名、状态名、税率、公式或条件。
- 不为了“页面好看”增加没有解释价值的图片。

## 数量建议

- 短术语说明：0–1 张精确图，1–2 张小黑图。
- 中等功能说明：1–2 张精确图，2–4 张小黑图。
- 复杂架构说明：2–4 张精确图，1–3 张小黑图。
- 用户指定数量时服从用户，但仍需指出重复或无价值的视觉任务。

## 任务卡字段

每个任务卡至少包含：

- `id` 与放置章节。
- 要回答的唯一问题。
- 支撑的 claim IDs。
- 读者读图后应得出的结论。
- 必须出现和禁止出现的元素。
- 标签语言、长宽比、文件名和替代文本。
- 供应方专属 QA 要求。
