# 输出与质量检查

## 规范产物顺序

1. `explanation-brief.yaml`
2. 精确图与概念插图资产
3. `index.html`
4. 单文件 HTML（如果需要）
5. PDF（如果需要）
6. `qa-report.md`

不得从 PDF 反推 HTML，也不得为单文件 HTML 重写一套正文。

## Bundle

- 所有本地引用使用相对路径。
- 目录和文件名只用 ASCII slug；页面正文可以使用中文。
- 页面不能引用输出目录外的绝对文件路径。
- 第三方运行库尽量本地化；必须在线加载时，不得声称支持离线。

## Single HTML

- 图片转为 data URL 或内嵌 SVG。
- CSS 与必要脚本内嵌。
- 禁止 `file://`、本机绝对路径和 HTTP(S) 运行时依赖。
- 断网打开并检查图片、导航和交互。

## PDF

- 使用 A4 和专用打印 CSS。
- 自动定向时，知识解释、产品说明选纵向；复杂流程、架构选横向。
- 隐藏交互控件，保留必要的链接文本或 URL。
- 标题避免孤行；表格允许合理跨页但表头重复；图片不得被裁切。
- 包含封面、目录、页码、来源与生成日期。
- 渲染每页为 PNG，逐页肉眼检查。

## qa-report.md 最小模板

```markdown
# QA Report

## Result
PASS / FAIL

## Automated checks
- [ ] 文件结构
- [ ] 相对资产完整
- [ ] 无未处理占位符
- [ ] 单文件离线依赖
- [ ] PDF 文件与逐页渲染

## Human checks
- [ ] 三层受众可读
- [ ] 视觉分工无重复
- [ ] 关键事实可追溯
- [ ] 桌面与移动端无溢出
- [ ] PDF 无裁切、乱码或缺图

## Unknowns and limitations
- 无 / 列表
```

最终只有所有必需检查通过时才能写 `PASS`。未生成的模式标为 `N/A`，不能伪装成已通过。
